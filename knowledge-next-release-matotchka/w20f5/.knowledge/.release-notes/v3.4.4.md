# Knowledge 3.4.4 RC5

Status: unpublished candidate (`RC5`). Full release gate: not run.
Package version: 3.4.4. Archive: `knowledge-v3.4.4.zip`.

This copy is audit revision `independent-audit.20261020.windows.4`, derived from the
supplied Windows follow-up. Its new handoff contains the exact runtime SHA.
The version and candidate label remain 3.4.4 RC5. New changes cover complete
verification evidence guards, TFR v2 finalization and Inspector visibility,
contained report writes, strict entitlement admission, owned fixture cleanup
and portable names in the standalone ZIP helper. Additional scenario-driven
fixes cover watcher attempt ownership, live task trust in the footer/Inspector,
canonical ZIP portability, per-attempt contained JSON guards, stable ingest
identities, exact Pinecone consent, complete Git rename paths and regular-file
metrics inventory. See
[current audit](../docs/verification-execution-contract.md) for scope and limits.
Native verification on Linux/macOS still refuses before worker/probe creation.
This revision receives fresh Windows verification; earlier Windows and Linux
results retain their parent identity. New Linux/macOS runs, live-provider
verification and the full release gate remain deferred.

The Windows continuation adds v2 command records, immutable batch receipts and
signed acceptance after confirmed Job Object teardown. Older or unacknowledged
KVE remains historical command evidence and cannot authorize new certification.
Team Status and Inspector now derive completion from each attempt's finalization
record after lock release. Missing records stay incomplete; failed release is
visible after reopening. Explicit retry creates a new attempt with its own ID.

RC5 strengthens lock ownership and native verification on the RC4 base.
Doctor exposes unsafe state/project locks as operational blockers; team status
also inspects its registry lock. Cleanup uses the directory identity and owner
bytes captured by the current acquisition. Flow finalization preserves the
primary result and starts optional Inspector onboarding only after release.

Native verification now separates work, progress and cleanup. Work timeout and
explicit cancellation latch the attempt; verified process termination and a
final cancellation-aware commit are required before ACK release. An incomplete
cleanup leaves an operational claim and recovery instructions. New v2 acceptance
binds both work and cleanup timing; historical v1 evidence retains its original
contract. See [the execution contract](../docs/verification-execution-contract.md).

RC4 prevents raw JSON parser excerpts in Inspector diagnostics from bypassing
child-output masking. Its source regression tests recognize Windows command
paths and native process termination results. Team Doctor test diagnostics retain
the inner flow log and child identity, rejecting uncontained or linked paths.
See the separate audit handoff
for original Windows evidence and historical observations. Those results do
not certify this derivative on Windows. The continuation handoff separates fresh
Windows evidence by source/runtime hashes from incoming Linux findings; POSIX
native execution remains unavailable.

RC3 incorporates the local audit corrections to RC2. The
[RC3 audit guide](../docs/audit-3.4.4-rc3.md) describes stricter recovery and
child-result validation, consistent Doctor ownership, evidence-path checks,
masked recording projections and narrowly validated updater journal additions.
Source-only regressions and audit receipts accompany the separate maintainer
handoff. This candidate does not claim that historical intermittent lock or
team-mode observations have been causally resolved.

An ordinary scoped repair could leave protected lifecycle findings open while
marking their context sources clean in freshness. That hid the files from
Doctor's current recheck view. Certification now uses artifacts from actual
successful lifecycle closures. Context-only sources retain their existing
freshness records; remaining protected findings also prevent a same-source
ordinary closure from clearing freshness. Exact protected closure still needs
passing native KVR evidence and its independently bound KDVR.

Recording blockers are visible in CLI results and a dedicated Inspector panel.
The agent contract requires immediate chat notification in the user's language,
including the blocked record, reason and available next step. Possible secrets
stay masked. Explicit, revocable non-secret classifications apply only to an
exact existing repository path, for one task or this project. Secret-key fields,
arbitrary secret text, and user-defined write boundaries stay protected.
The ordinary `skills/...` prefix no longer triggers the short-key detector.

These are local runtime and agent-contract controls. They do not provide a host
completion hook for arbitrary agents or guarantee that an external runner will
display a chat message. No automatic retry, user confirmation or broader write
permission is inferred from a blocked result.

Factual currency is an opt-in, review-bound v3 overlay. A single child request
must still be wrapped in an exact-input batch for issuance. Native KVE evidence
binds the batch and child request bytes along with the complete computed scope;
the receipt records `lifecycle_effect: none`, and raw lifecycle ledgers and
application risks remain open. See [the factual currency guide](../docs/factual-currency.md).

Legacy local v1/v2 prototype receipts are not accepted as v3 currency evidence.
Automatic migration, deletion, or reset of old receipts and indexes is not
implemented. Existing recording-path overrides also do not bypass strict
currency privacy checks. The exact CLI-check integration is supported only
from the checkout containing the runtime; no general central-install
integration is promised.

`sync-tracked` now preserves ignored module cards and non-lifecycle legacy
rows by default, reports preserved cleanup debt, and commits its queue pair
with exact read guards. `--preserve-history` explicitly selects that same
policy; malformed preservation flags fail before mutation. Generated tracking
may still leave the active registry. There is no destructive cleanup command.
The queue transaction does not cover every derived sync output.

Task Readiness before/after compares one frozen finding cohort and exact
occurrences; additional current debt is separate. Empty cohorts have no
numeric delta. Typed routing uses the full registry/card declaration, longest
matching ownership and conditional dependencies; physical directory scopes do
not become a wildcard for the root module. Large child JSON output has a
bounded capture limit, and spawn failures remain failures.

Final release certification, cross-platform release matrix and publication
are deferred. No full release gate or cross-platform matrix has been run for
this RC5 candidate.
