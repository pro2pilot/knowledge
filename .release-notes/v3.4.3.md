# v3.4.3 — covered recheck recovery and verification hardening

Knowledge 3.4.3 fixes a recovery gap: verifying a module could leave covered
historical recheck debt open. Exact source coverage and committed verification
evidence can now close those records together. Changed sources, incomplete
coverage and unrelated debt still require their own checks.

This release also includes the runtime and data-preservation corrections
described in [`docs/audit-3.4.3-audit.1.md`](../docs/audit-3.4.3-audit.1.md).
Install the `knowledge-v3.4.3.zip` asset from the
[GitHub release](https://github.com/pro2pilot/knowledge/releases/tag/v3.4.3).

- Inspector drains rejected oversized HTTP bodies without retaining data,
  with a bounded wait so clients can receive HTTP 413 reliably.
- Watchers subscribe only to selected source directories, excluding runtime
  trees before native traversal so transient lock releases cannot break watching.
- Explicit Python selection avoids unrelated OS launcher discovery and keeps
  failures bound to the selected executable.
- Live Mem0 setup and import probes isolate package telemetry writes from
  canonical provider configuration and use the same UTF-8 environment as
  live operations. Unicode storage paths remain stable during health checks.
- Windows lock release retries bounded sharing failures while checking the
  original directory identity and exact owner on every attempt. A successor
  lock or a persistent access failure remains protected. Acquisition tolerates
  renamed Windows directory handles only after proving a physical namespace
  transition; release checks the moved directory before deleting it.
- Watcher smoke uses a parent IPC stop request on Windows, waits for owned
  child termination and checks final running state before reporting teardown.
  Interrupted sync and forced termination are reported separately from success.
- Upgrade regressions exercise repeated updates of a used target with retained
  backups and deleted external-memory defaults; operator config and evidence
  remain protected. Unexpected target changes continue to fail closed.
- Import stops immediately when install-check fails, preserves its blocking
  diagnostics, and does not run ingest or sync or announce completed setup.

- Exact module verification can close covered historical `tracked_file_needs_recheck`
  debt and rebind invalid prior closures in the same atomic transaction. Valid
  prior closures, uncovered sources, other modules and protected findings remain
  untouched. Generated-only repairs cannot perform related trust repairs.
- Related closures bind to the primary KVR, source hashes, lifecycle occurrence
  and committed transaction. Budget and telemetry count a shared KVR once while
  validating every related closure. Replay preserves the complete closure list.
- Uncovered-file trust reasons require source-hash-bound file facts; both the
  source and fact register must be in the verified snapshot. Tests alone do not
  manufacture coverage. A subsequent sync preserves the verified coverage.
- Task finish uses its explicit task route rather than importing unrelated
  global routing/PR/criticality scope (including the correction developed during 3.4.2 testing).
- Upgrades detect the known obsolete project-root release gate. The optional
  migration backs it up and redirects to the maintained maintainer gate; if that
  gate is absent, it reports a blocked result. Custom project gates are preserved.
- Extension installation uses current entitlement names, authenticates Ed25519
  signatures against locally pinned publisher keys, verifies core compatibility
  and rejects unsafe IDs. Prefix-only and development signatures are rejected.

See `docs/upgrade-3.4.3.md` for the migration and extension manifest contract.
Doctor, task readiness, local tests and full release certification remain
separate outcomes. Unrelated operational debt is not resolved by this update.
